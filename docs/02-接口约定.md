# 接口约定（M0 起）

> 前后端唯一契约：统一响应、错误码、TraceId、命名与鉴权头。
> 改契约 = 同时改本文件、`backend.md`、`ARCHITECTURE.md` 与前端封装。

## 1. 基础约定

- 前缀：所有业务接口以 `/api` 开头（Vite 已代理到 `http://127.0.0.1:8080`）
- 编码：`application/json;charset=UTF-8`；字段 `camelCase`
- 鉴权：`Authorization: Bearer <token>`（M0-B04 起，`/api/auth/**` 除外）
- TraceId：请求可带 `X-Trace-Id`，响应头回显；不传则服务端生成 16 位
- 成功码固定为 `0`；失败码与 HTTP 状态码一致
- 在线文档：`http://127.0.0.1:8080/swagger-ui.html`（需登录的接口点 Authorize 填 token）

## 2. 统一响应体

```json
// 成功
{ "code": 0, "message": "成功", "data": { "username": "demo" }, "traceId": "18a1eda07c2c4269" }

// 失败（data 恒为 null，便于前端统一处理）
{ "code": 400, "message": "username: 不能为空", "data": null, "traceId": "18a1eda07c2c4269" }
```

| code | HTTP | 含义 | 前端动作 |
| --- | --- | --- | --- |
| 0 | 200 | 成功 | 取 `data` |
| 400 | 400 | 参数错误 | 直接提示 `message` |
| 401 | 401 | 未登录 / token 过期 | 清 token，跳 `/login` |
| 403 | 403 | 无权限 | 提示无权限 |
| 404 | 404 | 接口或资源不存在 | 提示 + 上报 traceId |
| 405 | 405 | 方法不支持 | 开发期问题 |
| 409 | 409 | 数据冲突（如用户名已存在） | 提示换一个 |
| 500 | 500 | 服务端异常 | 提示稍后重试，附 traceId |
| 502 | 502 | 上游模型调用失败 | 提示可重试 |
| 503 | 503 | 未配置模型密钥 | 提示配置 `DASHSCOPE_API_KEY` |

## 4. 鉴权接口（M0-B04 已实现）

| 方法 | 路径 | 请求体 | 响应 `data` |
| --- | --- | --- | --- |
| POST | `/api/auth/register` | `{ username, password, nickname? }` | `{ id, username, nickname }` |
| POST | `/api/auth/login` | `{ username, password }` | `{ token, username, nickname }` |
| GET | `/api/auth/me` | 头带 Bearer token | `{ id, username, nickname, role }` |

密码规则：8–32 位，至少含字母和数字；用户名 3–32 位。JWT 有效期 2h。

## 5. 聊天接口（M1-02 已实现）

| 方法 | 路径 | 请求体 | 响应 `data` |
| --- | --- | --- | --- |
| POST | `/api/chat` | `{ content, conversationId?, module?, model?, retry? }` | `{ conversationId, content, model, promptTokens, completionTokens, latencyMs }` |

- `content` 1–4000 字；`conversationId` 留空由后端生成（`c_` 前缀）；`module` 默认 `chat`；`model` 留空用 `qwen-plus`
- 带上已有 `conversationId` 时，后端取该会话最近 20 条消息作为上下文（M1-05）
- `retry: true` 表示重试上一轮失败/停止的回答：不新增 user 消息，旧的半截回答标为 `FAILED` 后重新生成
- 未登录 401；会话不属于当前用户 403；上游模型失败 502；未配置密钥 503

### SSE `/api/chat/stream`（M1-03）

- 请求体同 `/api/chat`；响应 `Content-Type: text/event-stream`，`Cache-Control: no-cache`
- 每帧形如 `data: {"type":"delta","content":"你"}`，空行分隔
- 顺序：`meta → delta* → usage → done`；出错时为 `meta → error`
- `done.finishReason`：`stop` 正常 / `length` 达到 `max-tokens`（默认 4096）/ `stopped` 客户端停止
- `meta.messageId` 为 assistant 消息主键，可用于后续历史定位
- 客户端断开连接会取消上游生成（服务端日志 `stream cancelled`）
- 前端解析：按空行切帧、取 `data:` 行 JSON，分发到 handlers（`frontend/src/chat/sseTransport.ts`）
- 注意：流结束的 `ASYNC` 二次 dispatch 需放行，否则前端拿不到 `done`（见 `backend.md` M1-03）
- 事件字段与示例见 `modules/chat.md` §4

### WS `/ws/chat`（M1-07）

- 握手：`ws://127.0.0.1:8080/ws/chat?token=<JWT>`（浏览器 WS 不能带 Authorization 头）
- 客户端首帧：与 `/api/chat` 相同的请求体（含 `retry`）
- 服务端帧：`ChatEvent` JSON，无 `data:` 前缀；顺序同 SSE
- `done/error` 后服务端主动关闭；客户端关闭连接 = 停止生成（消息标 `STOPPED`）
- Vite 已代理 `/ws` 到 8080；页面右上角 `SSE / WS` 可切换，选择存 `localStorage`

### 会话 `/api/conversations`（M1-05）

| 方法 | 路径 | 参数 | 响应 `data` |
| --- | --- | --- | --- |
| GET | `/api/conversations` | `module?`（默认不筛） | `[{ uid, title, module, lastMessageAt }]`，按最后消息时间倒序，最多 50 条 |
| GET | `/api/conversations/{uid}` | 路径参数 | `{ uid, title, module, messages: [{ id, role, content, status, tokensIn, tokensOut, latencyMs, model, createdAt }] }` |

- 只返回当前用户自己的会话；别人的会话 403，不存在 404
- 详情只含 `DONE/STOPPED` 且内容非空的消息，按 id 正序，最多 200 条
- 时间字段为本地时间 ISO-8601（如 `2026-10-26T09:41:02`），前端自行格式化为「09:41 / 昨天 / 10-24」

## 6. 前端使用建议

```ts
// 伪代码：统一解包
const body = await res.json()
if (body.code !== 0) {
  if (body.code === 401) auth.logout()
  throw new Error(`${body.message}（traceId: ${body.traceId}）`)
}
return body.data
```

- 不要依赖 HTTP 200 判断业务成功，只看 `code === 0`
- 报错提示里带 `traceId`，排查时对应后端日志 `[traceId]`
- 前端已封装 `src/api/http.ts`（注入 token、解包、401 清理）与 `src/api/auth.ts`
- `VITE_USE_MOCK=true` 时前端离线（登录与聊天都走 Mock）
