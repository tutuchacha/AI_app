# 接口约定（M0 起）

> 前后端唯一契约：统一响应、错误码、TraceId、命名与鉴权头。
> 改契约 = 同时改本文件、`backend.md`、`ARCHITECTURE.md` 与前端封装。

## 1. 基础约定

- 前缀：所有业务接口以 `/api` 开头（Vite 已代理到 `http://127.0.0.1:8080`）
- 编码：`application/json;charset=UTF-8`；字段 `camelCase`
- 鉴权：`Authorization: Bearer <token>`（M0-B04 起，`/api/auth/**` 除外）
- TraceId：请求可带 `X-Trace-Id`，响应头回显；不传则服务端生成 16 位
- 成功码固定为 `0`；失败码与 HTTP 状态码一致
- 在线文档：`http://127.0.0.1:8080/swagger-ui.html`（需登录的接口点 Authorize 填 token）

## 2. 统一响应体

```json
// 成功
{ "code": 0, "message": "成功", "data": { "username": "demo" }, "traceId": "18a1eda07c2c4269" }

// 失败（data 恒为 null，便于前端统一处理）
{ "code": 400, "message": "username: 不能为空", "data": null, "traceId": "18a1eda07c2c4269" }
```

| code | HTTP | 含义 | 前端动作 |
| --- | --- | --- | --- |
| 0 | 200 | 成功 | 取 `data` |
| 400 | 400 | 参数错误 | 直接提示 `message` |
| 401 | 401 | 未登录 / token 过期 | 清 token，跳 `/login` |
| 403 | 403 | 无权限 | 提示无权限 |
| 404 | 404 | 接口或资源不存在 | 提示 + 上报 traceId |
| 405 | 405 | 方法不支持 | 开发期问题 |
| 409 | 409 | 数据冲突（如用户名已存在） | 提示换一个 |
| 500 | 500 | 服务端异常 | 提示稍后重试，附 traceId |
| 502 | 502 | 上游模型调用失败 | 提示可重试 |
| 503 | 503 | 未配置模型密钥 | 提示配置 `DASHSCOPE_API_KEY` |

## 4. 鉴权接口（M0-B04 已实现）

| 方法 | 路径 | 请求体 | 响应 `data` |
| --- | --- | --- | --- |
| POST | `/api/auth/register` | `{ username, password, nickname? }` | `{ id, username, nickname }` |
| POST | `/api/auth/login` | `{ username, password }` | `{ token, username, nickname }` |
| GET | `/api/auth/me` | 头带 Bearer token | `{ id, username, nickname, role }` |

密码规则：8–32 位，至少含字母和数字；用户名 3–32 位。JWT 有效期 2h。

## 5. 聊天接口（M1-02 已实现）

| 方法 | 路径 | 请求体 | 响应 `data` |
| --- | --- | --- | --- |
| POST | `/api/chat` | `{ content, conversationId?, model? }` | `{ conversationId, content, model, promptTokens, completionTokens, latencyMs }` |

- `content` 1–4000 字；`conversationId` 留空由后端生成（`c_` 前缀）；`model` 留空用 `qwen-plus`
- 未登录 401；上游模型失败 502；未配置密钥 503
- SSE `/api/chat/stream` 在 M1-03 提供，事件协议见 `modules/chat.md`

## 6. 前端使用建议

```ts
// 伪代码：统一解包
const body = await res.json()
if (body.code !== 0) {
  if (body.code === 401) auth.logout()
  throw new Error(`${body.message}（traceId: ${body.traceId}）`)
}
return body.data
```

- 不要依赖 HTTP 200 判断业务成功，只看 `code === 0`
- 报错提示里带 `traceId`，排查时对应后端日志 `[traceId]`
- 前端已封装 `src/api/http.ts`（注入 token、解包、401 清理）与 `src/api/auth.ts`
- `VITE_USE_MOCK=true` 时前端离线（登录与聊天都走 Mock）
