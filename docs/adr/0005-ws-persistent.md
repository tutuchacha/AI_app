# ADR 0005：WebSocket 改为持久连接

- 状态：已采纳（M1-09）
- 日期：2026-10-26
- 关联：`0002-streaming-transport.md`（双通道）

## 背景

M1-07 的 WS 是「一条连接跑一轮」：每轮重新握手 + JWT 鉴权，停止靠关闭连接。
实测与 SSE 体验完全一致，且每轮多一次握手开销，没有体现 WebSocket 的价值。

## 决策

WS 改为**一次握手、多轮复用**：

- 客户端帧：`{"type":"chat",...}`、`{"type":"stop"}`、`{"type":"ping"}`。
- 服务端帧：`ChatEvent`（同 SSE）或 `{"type":"pong"}`。
- 同一连接同时只跑一轮；`stop` 只取消当前轮，连接保留给下一轮。
- 连接关闭等价于 `stop`；断线后下一次发送自动重连。
- 客户端每 20s 发 `ping`，45s 无 `pong` 视为假死并关闭。
- 页脚展示「握手次数 / 本连接轮数 / 首字耗时」，用于对比 SSE。

## 后果

- WS 才有真实差异：连接复用、双向控制、可测首字延迟；SSE 仍是最简默认通道。
- 后端需要按会话保存当前订阅，并用 `remove(key, value)` 防止旧轮完成回调误删新轮。
- 多实例部署时 WS 需要粘性会话或消息总线（M6 再处理）。
